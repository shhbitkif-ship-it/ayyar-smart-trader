# دفتر مأموریت‌های تیم هوش مصنوعی

این فایل مرجع وضعیت کارهای چندعاملی است. وضعیت‌ها فقط با شواهد واقعی تغییر می‌کنند.

| شناسه | نقش | مأموریت | معیار پذیرش | وضعیت |
|---|---|---|---|---|
| DATA-01 | کیفیت داده | بررسی timestamp کندل، freshness و معنای open/close time در XAUS و BIQUOTE | تست مرزی timezone/age و مستندات provider؛ بدون کاهش gate ایمنی | آماده شروع |
| DATA-02 | کیفیت داده | طراحی تفکیک EXPECTED_SESSION_BREAK از UNEXPECTED_GAP با تقویم معتبر بازار | منبع تقویم مستند، DST/تعطیلات پوشش داده‌شده، تست تاریخی؛ عدم پرکردن شکاف | مسدود تا تأیید تقویم |
| ENGINE-01 | موتور تحلیل | ممیزی قواعد NO_TRADE و توافق چندتایم‌فریمی | تست‌های مثبت/منفی، داده stale و gap باید fail-closed | آماده شروع |
| QUANT-01 | بک‌تست | ممیزی look-ahead، هزینه‌ها و walk-forward | آزمون خارج از نمونه و تست ضد نشت داده | آماده شروع |
| UI-01 | Android/UI | طراحی و پیاده‌سازی ناوبری تب‌محور | مسیرهای اصلی بدون منوی طولانی؛ تست build و navigation | آماده شروع |
| API-01 | Backend | ممیزی قرارداد API و observability | تست سازگاری، خطاهای واضح و عدم افشای secrets | آماده شروع |
| QA-01 | QA/Security | تدوین release gates و regression suite | CI باید تست‌های backend، worker، API و Android را پوشش دهد | آماده شروع |

## اولویت اجرایی
ابتدا DATA-01 و ENGINE-01 و QUANT-01؛ سپس UI-01 و API-01. DATA-02 تا زمانی که تقویم رسمی/قابل اتکای ساعات معاملات و تعطیلات تأیید نشده، نباید به‌صورت permissive پیاده‌سازی شود.
